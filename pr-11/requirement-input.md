## Description

With TCG_CICD_ENDPOINT_URL pointed at the tunnel, the trigger step failed with "curl: (3) URL rejected: Malformed input to a URL function" on four re-runs of the same job. GitHub's secret editor showed the right address, but the caret sat on a second line: the value ended in a newline, which curl rejects in a URL (and which would put a newline in the X-TCG-CICD-Token header next).

The trigger script now cleans both secrets first: keep the first non-blank line, drop carriage returns, keep only visible ASCII. Checked against the real tunnel with a trailing newline, CRLF, leading and trailing spaces, a leading newline, a non-breaking space and the URL pasted twice: each fails raw and reaches the endpoint (405 to a GET) once cleaned. A clean value is unchanged and an empty one stays empty, so the "is not set" check still fires. The block was also run as extracted from the YAML under bash -e.

CLAUDE.md and the workflow header note the change.
